Capture first-touch campaign values on Squarespace

A Squarespace site can load Attribution Tracker through code injection when its plan supports that feature. Start by verifying browser capture; connecting the values to a form is a separate integration step.

Attribution Tracker project guide for version 0.1.1. Prepared with AI assistance and checked against the linked platform documentation. These are implementation recipes, not reports of an end-to-end test in a customer account.

Use site-wide footer code injection

Code Injection is available on Core, Plus, Advanced, and some legacy plans. It is not supported on checkout pages. In the site's Code Injection settings, add the following script tags to the footer and save. Keep the library before your initializer:

<script src="https://cdn.jsdelivr.net/gh/jasenf/attribution-tracker.js@v0.1.1/dist/attribution-tracker.js"></script>
<script>
// Paste the initializer below here.
</script>

Install it across the campaign landing pages, not just the contact page. Otherwise a visitor who arrives on another page may lose the campaign parameters before capture. Custom code is outside Squarespace's normal support scope; use a test site or an unpublished copy before changing the live setup.

Connect your consent decision

The initializer below assumes your consent manager updates window.cookieConsent. That variable is a placeholder contract, not a built-in Squarespace API. Replace it with the site's real consent decision and wire the manager's change callback. Without an affirmative decision, capture stays off.

const hasAttributionConsent = () =>
  window.cookieConsent === true &&
  navigator.globalPrivacyControl !== true &&
  navigator.doNotTrack !== '1';

let tracker;
function syncAttributionConsent() {
  if (!hasAttributionConsent()) {
    tracker?.clear();
    tracker = undefined;
    return;
  }
  tracker = new AttributionTracker({
    consent: hasAttributionConsent
  });
}
syncAttributionConsent();
// Call syncAttributionConsent() when your consent manager changes.
// Read tracker?.getAll() only while hasAttributionConsent() is true.

Download the browser build from the versioned distribution. The privacy guide explains callback precedence and clearing stored values. Clearing browser storage cannot retract data already submitted elsewhere.

Keep form handling explicit

This recipe captures values in the page's browser context. It does not add fields to a Squarespace Form Block or guarantee that an injected input will reach a built-in storage integration.

For an HTML form that you control, use the native form example with a form endpoint that accepts the named fields. For a Squarespace Form Block, establish a supported field mapping and verify the saved submission before relying on it. Avoid selectors based on generated field IDs.

Check capture on the published site, after navigation as well as a full reload. If your site configuration navigates without reloading the document, do not assume footer code runs again on each page change.

Verify before using the result

  1. Visit a landing page with ?utm_source=newsletter&utm_campaign=launch, grant the configured consent, and check the stored values.
  2. Return without campaign parameters in the same browser. The original values should remain while storage is available.
  3. Withdraw consent and confirm the change callback clears stored attribution and prevents the form handoff.
  4. If you add a form integration, inspect both the outgoing request and the saved submission. Send only the fields the destination needs.

The library cannot connect devices, restore cleared storage, or recover a campaign visit that ended before consent. Start with UTMs and the referral label; full URLs and click IDs can carry identifiers.
