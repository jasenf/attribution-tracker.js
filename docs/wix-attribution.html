Capture first-touch campaign values on Wix

Use Wix dashboard Custom Code to run Attribution Tracker in the site's page context. An HTML embed widget is a different environment and should not be used as a shortcut for capturing the parent page's landing URL.

Attribution Tracker project guide for version 0.1.1. Prepared with AI assistance and checked against the linked platform documentation. These are implementation recipes, not reports of an end-to-end test in a customer account.

Add dashboard Custom Code

Your Wix site must be published with a connected domain. In Settings, open Custom Code, add a snippet for all relevant landing pages, select load once per visit, and place it at the body end. Load the library before the initializer:

<script src="https://cdn.jsdelivr.net/gh/jasenf/attribution-tracker.js@v0.1.1/dist/attribution-tracker.js"></script>
<script>
// Paste the initializer below here.
</script>

Use the category appropriate to your site's attribution use. Wix's Essential category can load before consent; choosing a category alone is not the same as connecting the initializer's consent decision. Do not set attribution to Essential just to make it run earlier.

Wix's Embed HTML element uses an iframe. Code inside it has its own page context, so it can see the embed's URL instead of the site's campaign landing URL. Use dashboard Custom Code for this capture recipe.

Wix also enforces frontend security restrictions, including protection of internal cookies. Verify that the library's own attribution cookie can be written and read on your published domain. Do not attempt to read Wix security cookies or bypass its protections.

Connect your consent decision

The initializer below assumes your consent manager updates window.cookieConsent. That variable is a placeholder contract, not a built-in Wix API. Replace it with the site's real consent decision and wire the manager's change callback. Without an affirmative decision, capture stays off.

const hasAttributionConsent = () =>
  window.cookieConsent === true &&
  navigator.globalPrivacyControl !== true &&
  navigator.doNotTrack !== '1';

let tracker;
function syncAttributionConsent() {
  if (!hasAttributionConsent()) {
    tracker?.clear();
    tracker = undefined;
    return;
  }
  tracker = new AttributionTracker({
    consent: hasAttributionConsent
  });
}
syncAttributionConsent();
// Call syncAttributionConsent() when your consent manager changes.
// Read tracker?.getAll() only while hasAttributionConsent() is true.

Download the browser build from the versioned distribution. The privacy guide explains callback precedence and clearing stored values. Clearing browser storage cannot retract data already submitted elsewhere.

Plan a supported handoff to Wix Forms

Capturing values does not automatically attach them to Wix Forms, Wix CRM, or a Velo submission. Those need a supported field API and a tested bridge between your custom code and the form's own runtime. Do not assume a global variable from dashboard code is available in Velo.

If you own a separate HTML form in the same page context, the HTML form guide explains its payload. For native Wix Forms, verify the form API for your editor and form version before building an adapter.

Verify before using the result

  1. Visit a landing page with ?utm_source=newsletter&utm_campaign=launch, grant the configured consent, and check the stored values.
  2. Return without campaign parameters in the same browser. The original values should remain while storage is available.
  3. Withdraw consent and confirm the change callback clears stored attribution and prevents the form handoff.
  4. If you add a form integration, inspect both the outgoing request and the saved submission. Send only the fields the destination needs.

The library cannot connect devices, restore cleared storage, or recover a campaign visit that ended before consent. Start with UTMs and the referral label; full URLs and click IDs can carry identifiers.
