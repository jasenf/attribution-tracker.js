Add first-touch UTM values to a Webflow form

A visitor may arrive through a campaign, return directly, and submit a Webflow form later. This setup keeps an allowed set of first-touch values in the browser and copies them into fields that Webflow can submit with the form.

Project guide for Attribution Tracker 0.1.1. Prepared with AI assistance and checked against the library source and current Webflow documentation. Test the finished form on your own Webflow staging site before using it in production.

Add four fields to the Webflow form

In the Webflow Designer, add a Div block inside the Form wrapper. Add four text inputs inside that div and give them these names:

  • attribution_utm_source
  • attribution_utm_medium
  • attribution_utm_campaign
  • attribution_ref

Set the div to display: none. Do not make the inputs required. Webflow documents this same basic hidden-field construction for its honeypot technique: ordinary inputs stay inside the Form wrapper while a containing div hides them.

This guide deliberately omits the full landing-page URL, referrer URL, and advertising click IDs. Those values can contain identifiers or sensitive query data. Expand the allowlist only when the receiving workflow has a defined need and the visitor has made the required consent choice.

Populate the fields without replacing Webflow's submit handler

Open the page settings and paste the following into the custom code area before </body>. Replace window.cookieConsent with the current decision from your consent manager, and call syncAttributionFields() from that manager's change callback.

<script src="https://cdn.jsdelivr.net/gh/jasenf/attribution-tracker.js@v0.1.1/dist/attribution-tracker.js"></script>
<script>
  const hasAttributionConsent = () =>
    window.cookieConsent === true &&
    navigator.globalPrivacyControl !== true &&
    navigator.doNotTrack !== '1';

  const fieldMap = {
    utm_source: 'attribution_utm_source',
    utm_medium: 'attribution_utm_medium',
    utm_campaign: 'attribution_utm_campaign',
    ref: 'attribution_ref'
  };

  let tracker;

  function setAttributionFields(data = {}) {
    for (const [key, fieldName] of Object.entries(fieldMap)) {
      const field = document.querySelector(`[name="${fieldName}"]`);
      if (field) field.value = data[key] || '';
    }
  }

  function syncAttributionFields() {
    if (!hasAttributionConsent()) {
      tracker?.clear();
      tracker = undefined;
      setAttributionFields();
      return;
    }

    tracker = new AttributionTracker({
      consent: hasAttributionConsent
    });
    setAttributionFields(tracker.getAll() || {});
  }

  syncAttributionFields();
  // Connect your consent manager's change callback to syncAttributionFields().
</script>

The code updates existing inputs when the page loads or the consent decision changes. It does not bind to the form's submit event, replace Webflow's form action, or send a separate network request.

Publish and verify the complete path

Webflow's page-level custom code does not run on the public site until you publish. Publish to your webflow.io staging domain first, then test these cases:

  1. Open the page with ?utm_source=newsletter&utm_campaign=launch and grant the consent used by your callback.
  2. Return to the same site without those parameters and submit the form.
  3. Check the saved submission in Webflow and confirm the expected attribution fields appear once with the original values.
  4. Withdraw consent, run the consent-manager callback, and confirm the fields are blank and the library's browser storage is cleared.
  5. Repeat with GPC or DNT enabled if your site promises to honor those signals for this use.

If the fields do not appear, confirm that they are inside the Form wrapper, have the exact names shown above, and were present when the page loaded. If the form sends to a third-party destination instead of Webflow, verify that destination's field-mapping rules separately.

Know what this setup does not do

Attribution Tracker stores the first touch in the current browser only. It cannot reconnect activity across devices, recover a campaign visit that happened before consent, or remove a value from a Webflow submission that was already sent.

For the platform steps behind this recipe, see Webflow's guides to adding and configuring forms, creating hidden form fields, adding page-level custom code, and reviewing form submissions. The general HTML form guide explains the same first-touch handoff without Webflow.
