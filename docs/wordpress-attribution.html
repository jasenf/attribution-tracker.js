Add first-touch attribution to WordPress

Keep the campaign that first brought a visitor to a WordPress site, then make those values available when they return. This recipe is for self-hosted WordPress sites where you can deploy theme or plugin code.

Attribution Tracker project guide for version 0.1.1. Prepared with AI assistance and checked against the linked platform documentation. These are implementation recipes, not reports of an end-to-end test in a customer account.

Load the library through WordPress

Put a copy of the versioned browser build in your child theme at assets/js/attribution-tracker.js. Create assets/js/attribution-init.js with the initialization code below. Add this PHP to your child theme's functions.php, inside its existing PHP block:

add_action('wp_enqueue_scripts', function () {
    wp_enqueue_script(
        'first-touch-tracker',
        get_stylesheet_directory_uri() . '/assets/js/attribution-tracker.js',
        array(), '0.1.1', true
    );
    wp_enqueue_script(
        'first-touch-init',
        get_stylesheet_directory_uri() . '/assets/js/attribution-init.js',
        array('first-touch-tracker'), '1.0.0', true
    );
});

The dependency makes WordPress load the library before the initializer. Use a child theme or a small site plugin so a parent-theme update does not overwrite your integration. Check that your theme calls wp_footer().

Connect your consent decision

The initializer below assumes your consent manager updates window.cookieConsent. That variable is a placeholder contract, not a built-in WordPress API. Replace it with the site's real consent decision and wire the manager's change callback. Without an affirmative decision, capture stays off.

const hasAttributionConsent = () =>
  window.cookieConsent === true &&
  navigator.globalPrivacyControl !== true &&
  navigator.doNotTrack !== '1';

let tracker;
function syncAttributionConsent() {
  if (!hasAttributionConsent()) {
    tracker?.clear();
    tracker = undefined;
    return;
  }
  tracker = new AttributionTracker({
    consent: hasAttributionConsent
  });
}
syncAttributionConsent();
// Call syncAttributionConsent() when your consent manager changes.
// Read tracker?.getAll() only while hasAttributionConsent() is true.

Download the browser build from the versioned distribution. The privacy guide explains callback precedence and clearing stored values. Clearing browser storage cannot retract data already submitted elsewhere.

Connect the form you actually use

For a native HTML form that you own, use the four-field form handoff. For a form plugin, create its supported hidden fields and populate them through the plugin's documented frontend API before it builds the request. AJAX forms may serialize their fields before a native submit listener runs.

This is not a universal Contact Form 7, WPForms, or Gravity Forms adapter. Confirm the values in your plugin's saved submission. WordPress.com and managed hosts can impose separate custom-code restrictions. Pasting scripts into a Custom HTML block may strip them when the user lacks unfiltered_html.

Verify before using the result

  1. Visit a landing page with ?utm_source=newsletter&utm_campaign=launch, grant the configured consent, and check the stored values.
  2. Return without campaign parameters in the same browser. The original values should remain while storage is available.
  3. Withdraw consent and confirm the change callback clears stored attribution and prevents the form handoff.
  4. If you add a form integration, inspect both the outgoing request and the saved submission. Send only the fields the destination needs.

The library cannot connect devices, restore cleared storage, or recover a campaign visit that ended before consent. Start with UTMs and the referral label; full URLs and click IDs can carry identifiers.
