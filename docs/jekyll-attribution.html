Guides / Jekyll and GitHub Pages

Keep first-touch attribution on Jekyll and GitHub Pages

Jekyll generates the page, and Attribution Tracker runs in the visitor's browser. You can keep first-touch campaign values on a static site without adding a tracking server.

Attribution Tracker project guide for version 0.1.1. Prepared with AI assistance and checked against the linked platform documentation. These are implementation recipes, not reports of an end-to-end test in a customer account.

Add a shared include

Download the versioned browser build into assets/js/attribution-tracker.js. Save the initializer below as assets/js/attribution-init.js. Create _includes/attribution.html:

<script src="{{ '/assets/js/attribution-tracker.js' | relative_url }}"></script>
<script src="{{ '/assets/js/attribution-init.js' | relative_url }}"></script>

Add {% include attribution.html %} before the closing body tag of the layout shared by your landing pages. The relative_url filter uses your configured baseurl, which matters for a GitHub Pages project hosted under a repository path.

If your layout comes from a theme gem, use the theme's documented include hook or override its layout locally. Preserve the layout's existing content, styles, and includes.

Connect your consent decision

The initializer below assumes your consent manager updates window.cookieConsent. That variable is a placeholder contract, not a built-in Jekyll and GitHub Pages API. Replace it with the site's real consent decision and wire the manager's change callback. Without an affirmative decision, capture stays off.

const hasAttributionConsent = () =>
  window.cookieConsent === true &&
  navigator.globalPrivacyControl !== true &&
  navigator.doNotTrack !== '1';

let tracker;
function syncAttributionConsent() {
  if (!hasAttributionConsent()) {
    tracker?.clear();
    tracker = undefined;
    return;
  }
  tracker = new AttributionTracker({
    consent: hasAttributionConsent
  });
}
syncAttributionConsent();
// Call syncAttributionConsent() when your consent manager changes.
// Read tracker?.getAll() only while hasAttributionConsent() is true.

Download the browser build from the versioned distribution. The privacy guide explains callback precedence and clearing stored values. Clearing browser storage cannot retract data already submitted elsewhere.

Choose a form destination

GitHub Pages hosts static files; it does not process a POST request for you. Keep your existing form service or backend, and use the HTML form handoff to add selected values. A provider that rejects unknown fields will need its field definitions updated first.

Build with bundle exec jekyll build, then inspect the generated page under _site. Both script URLs must resolve under the deployed project path. Avoid adding a second copy of the include in a nested layout.

Verify before using the result

  1. Visit a landing page with ?utm_source=newsletter&utm_campaign=launch, grant the configured consent, and check the stored values.
  2. Return without campaign parameters in the same browser. The original values should remain while storage is available.
  3. Withdraw consent and confirm the change callback clears stored attribution and prevents the form handoff.
  4. If you add a form integration, inspect both the outgoing request and the saved submission. Send only the fields the destination needs.

The library cannot connect devices, restore cleared storage, or recover a campaign visit that ended before consent. Start with UTMs and the referral label; full URLs and click IDs can carry identifiers.
